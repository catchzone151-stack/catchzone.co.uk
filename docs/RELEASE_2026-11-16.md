## Publishing from Replit (only after owner approval)

The Replit workspace may hold commits that are not on GitHub (workspace HEAD `ab7ed69`,
deployment `45ba233`, `feat/voice-replit-postgres` @ `9060ead` were not found on GitHub). Do not
discard them.

1. In the Replit Shell, record the current state:
   `git status && git log --oneline -3 && git branch --show-current`
   If there are uncommitted changes, commit them on their own branch (or `git stash`) first.
2. Fetch and check out the release branch:
   `git fetch origin claude/catchzone-website-finalisation`
   `git checkout -B release/website-finalisation FETCH_HEAD`
   `git log -1 --format=%H` must equal the SHA in the final report.
3. `npm ci && npm test && npm run build` — all must pass (`npm ci` applies the PostCSS override).
4. Confirm the Secrets pane still has `RESEND_API_KEY` (and `RESEND_FROM_EMAIL` if used); do not
   add any Soniox demo variables.
5. Deploy (Autoscale, `npm run build` / `npm run start`), then run the checks below.

Rollback: redeploy the previous deployment from Replit's Deployments history (or check out
`75a3163` and redeploy).
