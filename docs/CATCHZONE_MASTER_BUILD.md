Interfaces activate.

Light/data begins flowing.

Approx. 4.5 → 6.2 sec

→

Approx. 6.0 → 8.0 sec
------------------------------------------------------------

Camera moves toward or through part of the assembled system.

One digital surface expands.

30. WEBGL ARCHITECTURE
============================================================

Avoid dozens of independent canvases.

Prefer:

one carefully managed primary canvas for the intro/hero where appropriate

plus a separate lazily-loaded canvas only where a later experience such as the ecosystem genuinely requires it.

Do not ship Three.js to pages that don't need it.

Dynamic-import heavy client-only experiences.

Manage:

textures
materials
geometry
render targets
frame loops
event listeners
post-processing

correctly.

Dispose resources on teardown.

Pause unnecessary rendering when:

- tab is hidden
- section is well outside viewport
- reduced-motion mode applies
- low-performance tier applies

Use demand rendering where appropriate.

- hardware concurrency if available
- device memory if available
- renderer capabilities
- measured frame timing
- context health

Be defensive because browser hardware APIs may be unavailable.

============================================================
35. HIGH PERFORMANCE TIER
============================================================

For capable desktops:

- richer particle density
- higher DPR within sensible cap
- full geometry assembly
- advanced materials
- subtle post-processing
- richer light behaviour
- full camera choreography

Target a smooth 60fps experience on capable hardware.

Do NOT claim universal locked 60fps.

============================================================
36. BALANCED TIER
============================================================

For normal laptops/tablets:

- lower particle count
- simplified materials
- less post-processing
- lower DPR
- reduced shadow cost
- simpler effects
- same core visual story

============================================================
37. SAFE TIER
============================================================

For low-power devices, poor frame timing, WebGL problems, power constraints where detectable or reduced-motion users:

- lightweight DOM/CSS alternative
- static or minimal dimensional background
- no expensive shaders
- no essential 3D interaction
- reduced animations

All content and navigation must remain fully available.

WebGL must never be required to understand the site.

============================================================
38. RUNTIME PERFORMANCE ADAPTATION
============================================================

Monitor frame timing carefully without creating excessive overhead.

If sustained performance is poor:

downgrade effects.

Do not constantly switch up/down causing visual instability.

Use conservative thresholds and cooldowns.

Handle:

webglcontextlost
webglcontextrestored

gracefully where applicable.

The site must remain usable if the 3D layer fails.

Mobile:

- simplified geometry
- reduced camera travel

- tap/swipe ecosystem interactions
- different typography balance
- appropriate section spacing

Mobile should still feel premium.

Do not cook the user's phone GPU.
